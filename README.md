# Browser 1.0 — консольный браузер для Windows

**Консольный браузер для Windows. Без GUI-версии — только терминал.**

Browser — браузер на C++20, работающий прямо в консоли. Введи запрос или адрес — и страница отрисуется: заголовок, читаемый текст и кликабельные ссылки. Для сайтов, которым нужен настоящий рендер, есть команда `web` — страница открывается в отдельном окне на движке Chromium (WebView2), а офлайн-библиотека Wikipedia доступна через `wiki`.

## Возможности

- **Поиск** через HTML-версию DuckDuckGo (без JavaScript), с автоматическим переходом на Bing и Google при блокировках, CAPTCHA и пустой выдаче.
- **Реальные результаты**: ссылки-обёртки поисковиков (`duckduckgo.com/l/?uddg=`, `bing.com/ck/a?u=a1…`, `google.com/url?q=`) автоматически разворачиваются в целевые URL; служебные ссылки поисковика отфильтровываются.
- **HTTP/HTTPS** через WinHTTP с проверкой TLS-сертификатов, gzip/deflate, keep-alive, тайм-аутами, обработкой редиректов (301/302/303/307/308, до 8 hop'ов, включая относительные `Location`), условными запросами и кэшем.
- **Интернациональные домены (IDN)**: кириллические и другие не-ASCII домены автоматически преобразуются в punycode (`пример.рф` → `xn--e1afmkfd.xn--p1ai`).
- **HTML5-парсер** на Lexbor: заголовки (с маркером `■`), абзацы, списки (`•`/`◦`/`▪` с отступами), цитаты (`▎`), разделители (`―――`), таблицы (строки через `|`), блоки `<pre>` с сохранением форматирования, ссылки, изображения, метаданные; корректная обработка кодировок (UTF-8/UTF-16/Windows-1251 и др. через BOM, `Content-Type` и `<meta charset>`), HTML-сущностей и битой разметки.
- **Reader-режим**: автоматически вырезаются навигация, боковые панели, колонтитулы, оглавления, инфобоксы, списки литературы и cookie-баннеры (по тегам и class/id-маркерам) — текст начинается сразу с содержимого статьи. То же фильтрование применяется к ссылкам и изображениям.
- **Фоновая загрузка**: страницы грузятся в отдельном потоке — интерфейс не замирает, `Esc` отменяет запрос, новая навигация встаёт в очередь.
- **Быстрая клавиатурная навигация** без мыши: `j`/`k` или стрелки — по ссылкам, цифры — быстрый выбор, `o` — адресная строка, `/` — поиск на странице, `b`/`f`/`r` — история/обновление, `g`/`G` — края страницы, `Space` — листание.
- **Мышь**: подсветка ссылок и кнопок при наведении, клик по ссылке/кнопке/строке поиска, колесо прокрутки, защита от случайного срабатывания при двойном клике.
- **Вид «как браузер»**: панель навигации, адресная строка с текущим URL, заголовок страницы во вкладке и в заголовке окна консоли.
- **История, закладки, кэш**: `Ctrl+D` — закладка, `Ctrl+H` — история (открывается как кликабельный список), `Ctrl+B` — закладки; очистка истории, закладок и кэша командами или из текста.
- **Поля форм и ввод текста**: на страницах с HTML-формами отображается секция «ПОЛЯ ФОРМЫ» — текстовые поля, пароли (скрыты `••••••`), чекбоксы, radio-группы, выпадающие списки, скрытые поля и кнопки отправки. `Enter` — изменить текстовое поле (значение редактируется в адресной строке), `Enter` на чекбоксе/radio/select/submit — активировать, `Ctrl+Enter` — отправить форму с любого поля (как implicit submission в браузере). Поддерживаются GET (параметры в query) и POST (`application/x-www-form-urlencoded`, без кэша, редиректы 307/308 сохраняют POST, 301/302/303 деградируют в GET — как в браузерах). Относительные `action` разрешаются в абсолютные URL.
- **Вкладки браузера**: полоса вкладок вверху экрана (как в Chrome/Firefox). `Ctrl+T` — новая, `Ctrl+W` — закрыть, `Ctrl+Tab` / `Ctrl+Shift+Tab` — следующая/предыдущая, `Ctrl+1`–`Ctrl+9` — перейти к вкладке (9 — последняя). У каждой вкладки своё содержимое страницы, своя история «назад/вперёд», позиция прокрутки и выбор элемента. Мышью: клик по вкладке — переключение, `×` — закрыть, `+` — новая, средняя кнопка — закрыть вкладку. Максимум 12 вкладок.
- **Восстановление сессии**: открытые вкладки сохраняются в `data/tabs.txt` и переоткрываются при следующем запуске (каждая вкладка догружается при первом переключении на неё).
- **Сохранение страницы**: `Ctrl+S` пишет исходный HTML (или текст, если HTML недоступен) в `saved/<название>.html|.txt`.
- **Автодополнение адресной строки**: при вводе показываются до 8 совпадений из истории и закладок; `↑`/`↓` — выбор, `Tab` или `Enter` — подставить (повторный `Enter` — перейти), клик мышью — тоже.
- **Закладки на главной**: до 6 закладок отображаются под строкой поиска, клик открывает страницу.
- **История с датами**: записи истории хранят время визита; страница «История» и fallback-вывод показывают «5 мин. назад» / «3 дн. назад» / дату.
- **Изображения на странице**: секция «ИЗОБРАЖЕНИЯ» (до 40) — `j/k` выбирает, `Enter`/клик открывает полноэкранный просмотр: картинка рисуется truecolor-полублоками `▀` через WIC (ANSI). В просмотре `D` — скачать файл в `downloads/`, `Enter`/`Esc`/клик — назад.
- **Прогресс загрузки**: статус-строка показывает полученные байты («Загрузка… 1.2 МБ»).
- **Keep-alive соединения**: HTTP(S)-подключения к хостам переиспользуются между запросами (пул до 4 на хост) — повторные переходы по сайту быстрее; мёртвые соединения отбрасываются.
- **Поиск по странице**: `Ctrl+F` или `/`, повторный `Enter` — следующее вхождение; все совпадения подсвечиваются в тексте до перехода на другую страницу.
- **Загрузка файлов** в `downloads/` с прогрессом, отменой, **докачкой** и **автопроверкой SHA-256**: если рядом с файлом лежит `<имя>.sha256.txt` (как у релизов NEXUS и многих других), после закачки хеш сверяется автоматически — статус покажет `SHA-256 OK` или `MISMATCH`. Прерванную закачку (`.part`) можно продолжить — повторный `download <url>` докачает с места обрыва через HTTP Range. Список загрузок — `Ctrl+J`: Enter/клик открывает файл, `v` проверяет sha256, `e` открывает папку в Explorer, `r` обновляет. Загрузки ставятся в очередь — можно запускать несколько файлов подряд, в статус-строке видно `⇩ размер (+N в очереди)`. `Ctrl+Shift+O` открывает страницу в системном браузере. Ссылки на ~60 типов файлов (.exe, .zip, .pdf, .vsix, .dmg, .appimage, .torrent…) при Enter сразу скачиваются, а не открываются как страница.
- **Адаптация к размеру терминала**: перерисовка при изменении окна, компактный режим для узких консолей.
- **WebView2-окно** (`web <url>`): отдельное окно на движке Edge/Chromium с настоящим рендером HTML/CSS/JS — `web back|forward|reload|zoom-*|find <текст>|external|off`; в окне работают `F5`/`Ctrl+R`, `Alt+←/→`, `Ctrl+=/-/0`, `Ctrl+F`, `Ctrl+Shift+E`; загрузки файлов сохраняются в `downloads/`.
- **Офлайн-Wikipedia** (`wiki`): `wiki download <ru|en> [часть|all|N]` — резюмируемая закачка статей (только текст), `wiki portal|search|grep|open` — чтение и поиск прямо в WebView2-окне через `https://wiki.local/`.

## Требования

- Windows 10/11 (x64);
- Visual Studio 2022 или новее с компонентом **Desktop development with C++**;
- CMake 3.24+;
- Интернет при первой конфигурации (скачивается Lexbor v3.0.0).

## Сборка

```powershell
cmake -S . -B build
cmake --build build --config Release --parallel
```

Или готовые скрипты:

```powershell
.\build.cmd     # cmd
.\build.ps1     # PowerShell
```

Результат: `build\Release\Browser.exe`. Сборка Debug аналогична (`--config Debug`).

WebView2 SDK слинкован статически в `Browser.exe`. Сам **WebView2 Runtime** нужен только для команд `web` и `wiki` (на Windows 10/11 обычно уже установлен вместе с Edge); без него консольная версия работает полностью.

## Тесты

```powershell
cmake --build build --config Release --target browser_tests --parallel
.\build\Release\browser_tests.exe
```

176 проверок: кодировки UTF-8↔UTF-16, URL-кодирование (включая IDN/punycode), нормализация URL, разбор `Cache-Control`, round-trip кэша, определение кодировок (BOM, `Content-Type`, `<meta>`), парсинг HTML (включая битую разметку и страницы на 5000 абзацев), поиск на странице, распаковка ссылок-обёрток DuckDuckGo/Bing/Google, детект CAPTCHA-страниц, история и закладки. Фикстуры лежат в `tests/fixtures/`.

В поле поиска доступны команды: `back`, `forward`, `reload`, `home`, `history`, `bookmarks`, `bookmark add`, `clear-history`, `clear-history-older <дн>`, `export`, `import <файл>`, `bookmarks-clear`, `cache-clear`, `search <текст>`, `open <адрес|номер>`, `edge <адрес>` (рендер через headless Edge; также `Ctrl+Shift+E` на текущей странице и авто-fallback для JS-страниц без текста), `downloads`/`stop`/`pause` (пауза очереди загрузок), `download <url> [имя]`, `sync`/`sync push`/`sync pull`/`sync status` (синхронизация через GitHub Gist, нужен `gh`), `web <url>` (страница в окне WebView2/Chromium; `web back|forward|reload|zoom-*|find|external|off`), `wiki ...` (офлайн-Википедия: `download <ru|en> [часть|all|N]`, `portal`, `search`, `grep`, `stop`), `help`, `exit`.

### Синхронизация через GitHub Gist (опционально)

Если установлен и залогинен GitHub CLI (`gh auth login`), команда `sync push` отправляет историю, закладки, вкладки и настройки в секретный Gist (id сохраняется в `data/settings.txt` как `gist=<id>`), а `sync pull` на другом компьютере забирает их обратно. `sync` без аргументов показывает статус. Без `gh` команды безопасно сообщают об ошибке — ядро браузера работает и без синхронизации.

Дополнительно: RSS/Atom-ленты открываются как читаемый список новостей; `<meta refresh>` на страницах обновляет её автоматически; таблицы выравниваются по колонкам.

## Архитектура

```
src/
  browser.h        — общие структуры, константы, объявления
  util.cpp         — UTF-8↔UTF-16, URL, кодирование, SHA-256, пути данных
  network.cpp      — WinHTTP: запросы, редиректы, кэш (ETag/Last-Modified), keep-alive
  html.cpp         — определение кодировки + парсинг Lexbor HTML5
  storage.cpp      — история, закладки, экспорт/импорт HTML, внутренние страницы
  feeds.cpp        — детект RSS/Atom/RDF и reader-рендер лент
  downloads.cpp    — очередь загрузок (до 3 параллельно), resume, SHA-256,
                     страница browser://downloads
  sync.cpp         — синхронизация данных через GitHub Gist (gh CLI)
  app.cpp          — навигация, вкладки, поиск, async-загрузка, prefetch
  console_ui.cpp   — консольный интерфейс: отрисовка, мышь, клавиатура
  wvhost.cpp/h     — WebView2-окно (Chromium) для `web`/`wiki`
  wiki.cpp         — офлайн-библиотека Wikipedia (ru/en), wiki.local
  main.cpp         — точка входа + fallback-режим
tests/             — unit-тесты и HTML-фикстуры
```

Поток загрузки: `console_ui` → `LoadJob` (URL или поисковый запрос) → worker thread → `FetchPage` (WinHTTP + кэш + парсер) → `PollAsyncLoad` коммитит результат в UI-потоке. Глобальное состояние страницы изменяется только из UI-потока.

## Текстовый fallback-режим

Если консольный UI недоступен, доступны команды: `open <url|N>`, `search <words>`, `post <url> <urlencoded-body>`, `save`, `back`, `forward`, `reload`, `home`, `history`, `bookmarks`, `bookmark add|open N`, `find <text>`, `images`, `image N`, `edge <url>`, `download <url> [name]`, `downloads`, `stop`, `pause`, `sync push|pull`, `prefetch`, `export`, `import <file>`, `history-clear-older <дн>`, `cache-clear`, `clear-history`, `stats`, `help`, `exit`.

## Данные

Все пользовательские данные лежат **рядом с Browser.exe** (папки создаются при первом запуске, не зависят от рабочей директории — ярлык можно запускать откуда угодно):

- `cache/` — HTTP-кэш (тело + meta с ETag/Last-Modified/max-age);
- `data/history.txt` — история (хранится хвост до ~500 записей);
- `data/bookmarks.txt` — закладки;
- `data/tabs.txt` — URL открытых вкладок и позиция прокрутки (восстановление сессии, включая `browser://downloads`);
- `data/settings.txt` — `downloads=<путь>` (своя папка загрузок), `theme=light|dark`, `gist=<id>` (привязка синхронизации);
- `saved/` — страницы, сохранённые через `Ctrl+S`;
- `downloads/` — загруженные файлы.

## Известные ограничения

- Это **не** полноценный браузер: CSS-вёрстка, JavaScript, canvas, видео и SPA не исполняются. Сайты, строящие контент только через JS, покажут мало текста — для них есть поиск и прямые ссылки. Страница отображается в «reader-режиме»: сохранена структура (заголовки, списки, таблицы), но не пиксельная вёрстка оригинала.
- Рендеринг — текстовая модель: заголовки, абзацы, списки, таблицы (как текст), ссылки. Изображения из секции «ИЗОБРАЖЕНИЯ» открываются полноэкранным truecolor-просмотром (WIC + ANSI полублоки); `D` скачивает файл в `downloads/`.
- Поддерживаются только HTTP/HTTPS. `file://`, `ftp://`, `mailto:` и прочие схемы отклоняются.
- Проверка TLS-сертификатов включена и не отключается. Редиректы https→http выполняются (как в обычных браузерах), но содержимое передаётся по открытому каналу.
- Очень большие страницы ограничены 64 МиБ на ответ и 50 000 символов отображаемого текста; список ссылок — до 150, полей формы — до 120, форм — до 20.
- Формы: поддерживаются обычные HTML GET/POST-формы без JavaScript. Не поддерживаются: `enctype=multipart/form-data`, `input[type=file]`, `<select multiple>`, `formaction`/`formmethod` на кнопках, отправка по `Enter` внутри одноимённых полей без явного submit (используйте `Ctrl+Enter`), textarea с переносами строк (ввод однострочный). Radio-группы с одинаковым `name` в одной форме корректно снимают выбор с соседей; `<option value>` учитывается при отправке.
- Загрузки ограничены 2 ГиБ; отмена — по окончании текущего буфера чтения.
- В обычной консоли Windows (не Windows Terminal) часть ANSI-цветов и truecolor-картинок может отображаться упрощённо — интерфейс остаётся читаемым.
